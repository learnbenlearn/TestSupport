Test Support

Example

To use the data generation framework, create a class that extends TestSupport.DataGeneration like below: 
    
    @IsTest
    public class AccountTSExample extends TestSupport.DataGeneration {
        protected override String getSObjectType() {
            return 'Account';
        }

        public AccountTSExample() {
            super();
        }
        public AccountTSExample(TSDataGenerationConfig config) {
            super(config);
        }
        public AccountTSExample(TSDataGenerationConfig config, List fieldSpecs) {
            super(config, fieldSpecs);
        }

        protected override Map loadDefaultSpecsByField() {
            Boolean stateAndCountryPicklistsEnabled = Schema.SObjectType.Account.fields.getMap().containsKey('ShippingStateCode');

            Map defaultSpecsByField = new Map{
                Account.Name => new CounterSuffixField(Account.Name, 'Test Account '),
                Account.Phone => new TestSupport.TestDataField(Account.Phone, '223 4567890'),
                Account.ShippingStreet => new TestSupport.TestDataField(Account.ShippingStreet, '1 Beaver Stadium'),
                Account.ShippingCity => new TestSupport.TestDataField(Account.ShippingCity, 'University Park'),
                Account.ShippingPostalCode => new TestSupport.TestDataField(Account.ShippingPostalCode, '16802')
            };
            if(stateAndCountryPicklistsEnabled) {
                defaultSpecsByField.put(Account.ShippingStateCode, new TestSupport.TestDataField(Account.ShippingStateCode, 'PA'));
            } else {
                defaultSpecsByField.put(Account.ShippingState, new TestSupport.TestDataField(Account.ShippingState, 'Pennsylvania'));
            }
            
            return defaultSpecsByField;
        }
    }
Each implementor must define the getSObjectType() and loadDefaultSpecsByField() methods. getSObjectType() returns the API name of the sObject to generate data for. loadDefaultSpecsByField() returns a map specifying default values for the generated records. These can be static values defined through the TestSupport.TestDataField class or dynamic values defined through subclasses like CounterSuffixField.

Example Use

Once the `TestSupport.DataGeneration` subclass is created for the sObject, the generator can be used to create mock records like in the following example: 
    
        @IsTest
        private class AccountTSExampleUse {
            @IsTest
            private static void testAccountGeneration() {
                AccountTSExample generator = new AccountTSExample(
                    TSDataGenerationConfig.builder().setMode(TSGeneratorMode.SINGLE_RECORD).setGeneratorReturnValue(
                        TSGeneratorReturnValue.NEW_RECORDS
                    ).build()
                );
                List generatedAccounts = (List) generator.generate();

                Boolean stateAndCountryPicklistsEnabled = Schema.SObjectType.Account.fields.getMap().containsKey('ShippingStateCode');
                Assert.areEqual('Test Account 0', generatedAccounts[0].Name);
                Assert.areEqual('223 4567890', generatedAccounts[0].Phone);
                Assert.areEqual('1 Beaver Stadium', generatedAccounts[0].ShippingStreet);
                Assert.areEqual('University Park', generatedAccounts[0].ShippingCity);
                if(stateAndCountryPicklistsEnabled) {
                    Assert.areEqual('PA', generatedAccounts[0].ShippingStateCode);
                } else {
                    Assert.areEqual('Pennsylvania', generatedAccounts[0].ShippingState);
                }
                Assert.areEqual('16802', generatedAccounts[0].ShippingPostalCode);
            }
        }
The subclass can be instantiated using the TSDataGenerationConfig builder, which includes fluent setters to configure the number of records created, the return value of calls to the generate() method, generation of master records if the sObject is the detail in a master-detail relationship, generation of fake record IDs, whether the default field values defined in the subclass should be used, and the generator mode. The generator mode acts as a shorthand for the number of records to generate - TSGeneratorMode.SINGLE_RECORD will create a single record, while TSGeneratorMode.BULK_RECORDS will create 200 records. The generator return value can be TSGeneratorReturnValue.NEW_RECORDS (meaning that calls to generate() will return only newly created records) or TSGeneratorReturnValue.ALL_RECORDS (meaning that calls to generate() will return all records that have been generated by that class instance).

When instantiating the TestSupport.DataGeneration subclass, custom field value specifications can be provided to the constructor. If a value is specified for a field in both the default specifications returned by the implementation of loadDefaultSpecsByField() and the custom specifications, the custom specification will take precedence.
